# BEOPS structure contract, 2026-09-11

Status: current
Author: Codex
Public surface: https://3esign.github.io/beops/

This file answers one question: when a file appears in Beops, is it source, proof, generated public
data, generated private audit, live memory or residue?

## Rule

Everything is subordinate to the public site in one of four ways:

1. It is a source for the site: code, registries, collectors, tests, styles, basemap and static context.
2. It is proof behind the site: provenance ledger, corrections, evidence hashes and legal frame.
3. It is generated public state used by the site or public mirror: snapshots, history, watch readings,
   permission dataset, generated maps and daily live reports.
4. It is internal preparation: paper drafts, trails, scratch, scheduler tools and local live memory.

Anything that fits none of these is residue until named.

The public site is not only an output but the first health surface. `npm test` proves the generated
artefact before publication; `npm run test:site` asks GitHub Pages after publication whether the
live interface still equals the public export and whether the embedded pages answer.

## Generated public state

These files are deliberately not source-controlled in the private repo. They are regenerated from
source/proof/live memory and copied to the public mirror by the publisher when present:

- `public/live-snapshot.json`
- `public/history.json`
- `public/watch.json`
- `public/dataset/permission-landscape/`
- `research/observations/live/REPORT_*.md`
- `research/05-design/studies/slojevi*.svg`

The public mirror is the archive of these live outputs. The private repo is the source and proof of
how they were made.

## Generated private audits

- `research/06-paper/PAPER_STAMPS.json` is derived from paper files and git history.
- `research/08-provenance/CORRECTION_TIMES.json` is derived from `CORRECTIONS.md` and git history.

They may exist on disk, but their authority is the generator plus source record, not a hand-edited JSON file.

## How to see surplus and missing

Surplus:

- A tracked file outside the declared root files and root directories.
- A Markdown research document not named in `research/README.md`.
- A generated file that becomes tracked without being named in `STRUCTURE_CONTRACT.json`.
- A file in a public dataset folder that the dataset manifest did not declare.

Missing:

- A public-site fact with no source, writer and publication route.
- A scheduled task not present in `tools/beops_tasks.ps1`.
- A current paper or decision not reachable from `research/README.md`.
- A generator that writes a real artefact during a test instead of using a temp output or an ignored generated file.

The machine-readable copy is `research/STRUCTURE_CONTRACT.json`; `research/test_structure_contract.py`
keeps this contract connected to git, `.gitignore` and `publish_github.ps1`.
